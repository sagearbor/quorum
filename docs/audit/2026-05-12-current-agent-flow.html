Primary data flow (human contribution at a station)

1.Laptop at ?station=N posts to POST /quorums/<id>/contributions with hardcoded user_token:"anon-local".
2.routes.py invokes agent_engine.process_agent_turn(quorum_id, role_id, station_id, user_message).
3.agent_engine loads role + (empty) agent definition + last-10 station_messages + cross-station insights (Jaccard) + relevant docs + pending A2A requests.
4.Builds messages array: SYSTEM (stable, Azure-cached) → CONTEXT block → history → latest user msg → _call_llm.
5.LLM reply persisted to station_messages; tags extracted; substantive replies published to agent_insights (other stations pick this up next turn via Supabase Realtime).
6.autonomy_loop (if autonomy_level>0) polls agent_requests; picks a random active role; runs process_a2a_request. Race window: 1.5–3s.
7.WebSocket broadcast via ws_manager → frontend dashboard updates. Supabase Realtime ALSO fans out new rows.
8.Avatar speaks synthesisText via browser SpeechSynthesis. Including error fallbacks.

What does work

  • Three-tier LLM pipeline (deterministic keyword → conflict detection → final synthesis) with mock provider gated by QUORUM_TEST_MODE.
  • Per-station conversation history (station_messages) with prompt-cache-friendly system message layout.
  • Cross-station insight routing — actually does propagate insights across roles by tag overlap (just sub-optimally; should be embeddings).
  • Versioned agent_documents with audit trail.
  • Frontend realtime: Supabase channels for contributions, health, artifact, station_messages, documents, A2A requests.
  • Avatar gaze + emotion tracking (and now camera-picker — PR #13 fixes lid-closed flicker).
  • Architect agent and autonomy loop scaffolding — the BONES are right, the implementations are what's stubbed.
