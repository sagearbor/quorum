10.1 Write agent definition YAMLs for all demo roles
critical ~90–120 min
Why: apps/api/agents/definitions/ is currently empty. The IRB Officer and the Patient Advocate emit nearly identical replies, differing only by name substitution. The whole "distinct AI personas deliberating" demo story is fiction until this lands. Highest leverage fix on the list.
Create
apps/api/agents/definitions/medical_pi.yaml · irb_officer.yaml · biostatistician.yaml · patient_advocate.yaml · regulatory_affairs.yaml · ethics_reviewer.yaml · project_manager.yaml
Schema
name, slug, model, temperature, max_tokens, instructions (300–500 word persona), domain_tags (8–15 tags), authority_rank_hint.
Done when
  • New test tests/test_agent_definitions.py loads every YAML, validates schema, asserts unique slugs and non-empty instructions.
  • Manual check: 3 turns with 3 roles at autonomy 0.5 — assistant messages differ visibly in vocabulary, concerns raised, and recommendation framing.
10.2 Fix autonomy loop double-processing race via CAS pending→processing
critical ~1h with tests
Why: At autonomy_level=1.0 the loop tick can drop to 1.5s — well below typical LLM latency. The same agent_requests row gets picked twice → duplicate LLM calls, duplicate insights, duplicate WebSocket broadcasts. Visible on stage as repeated agent messages.
Edit
apps/api/autonomy_loop.py:138-151 · apps/api/agent_engine.py:372-380
Change
Before process_a2a_request(), do an atomic CAS: .update({"status":"processing"}).eq("id", req["id"]).eq("status","pending"). If the response shows 0 rows updated, SKIP — another worker/tick claimed it. Add .eq("version", req["version"]) on the final status update inside process_a2a_request.
Done when
  • New test tests/test_autonomy_race.py: two concurrent asyncio.gather ticks against the same pending request; exactly one LLM call observed (mock counter).
10.3 Implement A2A HTTP wire (httpx POST with retries + Supabase fallback)
critical ~1–2h
Why: apps/api/a2a/a2a_client.py:29-44 logs and returns {"status":"sent"} without making an HTTP call. Every "A2A dispatched" log line is a lie. Pre-expo we won't run separate per-role HTTP services, so most POSTs will fall back to the Supabase queue — but the implementation must be correct so Phase 11 can register real endpoints later without changing anything else.
Edit
apps/api/a2a/a2a_client.py
Use
httpx.AsyncClient · 5s timeout · 3 retries with exponential backoff (0.5s, 1s, 2s).
Contract
  • 2xx with JSON → return body.
  • 4xx/5xx/timeout/conn-error → log warning, return None.
  • Caller falls through to Supabase agent_requests enqueue (audit every call site).
Done when
Tests in tests/test_a2a_client_http.py covering 2xx / 500 / timeout. Startup logs a warning if _agent_registry is empty.
10.4 Station-paired QR claim flow — participants table + /pair route + rotating JWT
critical ~3–4h depends: 10.2
Why: Today user_token: "anon-local" is hardcoded for every contribution (quorum/[id]/page.tsx:290) and QR codes encode the same station URL phones just open the laptop dashboard. Two attendees scanning the same QR collide on station_id="station-N" and the agent conversation interleaves. This is the #1 visible-failure-on-stage risk.
New migration
supabase/migrations/2026XXXX_pairing_and_participants.sql — tables participants, station_sessions, pairing_tickets.
New endpoints
  • POST /sessions/station-claim → 201 {station_session_id, user_token_anon, expires_at} (4h TTL)
  • POST /sessions/pair-ticket → 201 {ticket_jwt, expires_at} (90s TTL, signed HS256)
  • POST /sessions/claim → 201 {device_session_id, participant_id, role_id, role_name} (single-use ticket consumption)
  • POST /sessions/heartbeat → 204 (updates participants.last_heartbeat_at; foundation for 10.10)
JWT
PyJWT · HS256 · secret QUORUM_JWT_SECRET (32+ chars) · payload {sub, jti, role_id, exp}.
Frontend laptop
On station page load, call /sessions/station-claim; sessionStorage stores result. Rotate /sessions/pair-ticket every 60s; render the rotating ticket as a QR pointing to https://<host>/pair?ticket=<jwt>.
Schema
Add participant_id column to station_messages and contributions (nullable; populated on new rows).
Done when
tests/test_pairing.py covers happy path, ticket expiry, double-consume (409), wrong signature (401), rate limit (max 1 ticket per 5s per station_session_id).

10.6 Never speak the error — graceful avatar fallback
high ~30 min
Why: agent_engine.py:216 returns the literal string "I encountered an issue processing your message" on LLM exceptions. That string is treated as a normal assistant reply and the avatar SPEAKS IT on the 60-inch projector. Audience reads it as "the AI is broken."
Backend
Return a structured sentinel: {"status":"facilitator_paused","reason":"<llm_unavailable|tool_error|other>"}. Route serializes with HTTP 200 + paused: true.
Frontend
useAvatarController.ts — when reply.paused === true: skip speak(), set IdleScene to a thinking-cycle, show a "Facilitator paused — reconnecting" pill on AvatarPanel. Pill auto-dismisses on next successful reply.
Bonus
Architect panic key Shift+Cmd+M → POST /events/<slug>/panic {muted: true} mutes all autonomy + TTS across the event.

10.8 RLS lockdown — read-open, write-service-role-only
high ~30 min
Why: All seven agent tables have FOR ALL USING (true). Anyone reading the Supabase URL from devtools (visible on every frontend request) can write arbitrary rows during the demo.
New migration
For each of agent_configs, station_messages, agent_documents, document_changes, agent_insights, agent_requests, oscillation_events:
  • FOR SELECT USING (true)
  • FOR INSERT/UPDATE/DELETE gated on auth.role() = 'service_role'
Audit
Grep apps/web/src/ for .insert/.update/.delete against agent_* and station_messages. Any direct write must be routed through FastAPI service role.
Done when
tests/test_rls_lockdown.py — anon-key client attempts insert into station_messages, asserts 403.
10.9 Disable / LLM-synthesize the auto-contribute concatenation
high ~10 min (off) / ~40 min (synthesize)
Why: At autonomy_level >= 0.7, agents auto-submit contributions by string-joining their last 3 assistant messages. Fragment salad: "The eGFR threshold should be 45. [...] Further review needed." That feeds the Tier 3 artifact synthesis and the final demo artifact reads poorly.

10.10 Heartbeat / presence — detect walked-away attendees
medium ~1h depends: 10.4
Why: If a station user walks away, the agent currently keeps talking to no one — and at autonomy > 0 the projector keeps generating turns for that empty seat. The foundation (POST /sessions/heartbeat) was already added in 10.4; this item wires the consumer side.
Backend
participants_is_active(p) → now() - last_heartbeat_at < 90s. Autonomy loop: when a role has no active participant and no human contribution in the last 5min, agent emits a one-time "I'll wait for <role_name> to return" message, then suspends turns for that role until heartbeat resumes.
Frontend
ParticipantPresenceDots component — green / yellow (idle >30s) / grey (walked-away >90s). Subscribes to participants via Supabase Realtime.
Done when
Simulated heartbeat lapse flips role status within 30s on the dashboard.
